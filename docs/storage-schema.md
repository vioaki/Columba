# 存储与升级

当前业务库 `user_version=6`，日志库 `user_version=3`。自动升级入口只接受空库、当前库和最新旧结构（业务 2 / 日志 1）；不扫描历史目录，不自动清空未知格式。

业务库保留渠道、模型、调用 Key、设置和原生续接归属。设置保存模型调度、价格映射/覆盖和 `migration-report`。日志库保留用量、系统日志及独立的 `billing_attempts`；账目用请求 ID＋尝试序号作为唯一键。诊断清理与用量重置不删除账目。

启动在打开服务和写入器之前执行升级，并持有升级锁。旧库通过 SQLite `VACUUM INTO` 创建包含已提交 WAL 的一致备份；两库和必要配置保存在业务库旁的 `columba-upgrade-*` 目录。`<业务库>.upgrade.json` 记录恢复状态。两库各在事务内迁移，完整性检查通过后才启动服务。失败恢复成套备份；中断后的下一次启动先恢复，再重试升级。备份保留供人工回退。

保留有效凭据、渠道、模型、调用 Key 和历史用量。旧用量写入账本为 `historical_unpriced`，不套用当前价格。助手专用 Key 不转为推理 Key；已退役助手、组和协议数据可在备份中找到。

只有能无歧义映射到同一个原始模型 ID 和协议的旧组才迁移调度。冲突/跨模型组回到默认。标准协议转为固定原生类型；自定义或不明确绑定保留连接资料并停用，原因记录在迁移报告。客户端必须改用原始模型 ID。

所有迁移测试都由 `storage/testdata/latest-business.sql` 和临时日志库生成，覆盖 WAL、未知版本拒绝、失败恢复、重启幂等和加密凭据保留。恢复整个数据目录时必须保留原有加密密钥；环境变量密钥不会写入备份。
